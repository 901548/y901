# 代码审查记录（2026-11-23）

本轮对 `y901` 做了一轮"读源码找真 bug"的审查，范围集中在
`y901-ui`（布局/脏区/绘制遍历）、`y901-widgets`（新加的 `TextArea` 与既有控件）、
`y901-render`（软光栅、字形引擎、图集）。

**原则**：每条发现都必须能给出 `file:line` + 可触发输入；修复必须带回归测试，
并且**验证过测试能抓到旧 bug**（把修复临时撤掉，测试要红）。没有证据的"感觉可能有问题"不写进来。

附带修掉的工程缺陷：

- `ui/layout.rs`：`flex_measure_into` 的文档与 `#[allow(too_many_arguments)]` 挂在了 `clamp_axis` 上；
- `ui/layout.rs`：`arrange` 里百分比只看"两个轴都有限"，与 measure 口径不一致（潜在分歧）；
- `ui/layout.rs`：`flex_arrange` 的 `fixed_total` 来自 measure 快照、`main` 却重新读 `flex()`（同源性问题）；
- `ui/tree.rs`：`collect_ink_margins` 的 `reserve` 用了一个**已被搬空**的表长度，静默失效；
- `ui/tree.rs`：重新出现的节点（上一轮被 `is_open` 关掉、这一轮打开）不再被标脏；
- `scripts/sync-doc-numbers.ps1`：改不动行内 `targets=`，且会把历史叙述里的"N 项忽略"改成当前值。

## 已知但**未**修（附理由）

| 项 | 为什么不修 |
|---|---|
| `Dimension::Percent` 在 `measure` 里按"约束上限"解析、在 `arrange` 里按"实际 rect"解析 | 真实语义分歧，但改动会改变大量既有布局结果；在"哪个才对"没有定论前动它，属于用修复引入新风险。已记录待评估（CSS 的做法是"父高度不确定时按 auto"）。 |
| `Widget::cache_key()` 与 `id_key(id)` 的键空间约定 | 所有内置实现都满足；第三方控件返回非 id 派生键时会失配。属 API 契约陷阱，需要设计层面的决定（统一 `key_of()` 助手或把契约写进文档）。 |
| 弹出层不在 `rects` 索引里 | 既有行为，且 `push_popup`/`close_popup` 会整窗/矩形标脏兜住，属契约瑕疵而非缺陷。 |
| `layout()` 中途 panic 会让 `rects` 索引表一直为空 | 工作区内没有任何 `catch_unwind`；panic 后进程处于未定义状态。与渲染 scratch 缓冲的处理保持一致（那里也接受同类风险）。 |
| `render::atlas::Atlas` 的紧凑化/尺寸校验问题 | 该模块当前**只被自身测试使用**（生产走 `MyFontEngine` 自己的 packer），修它没有线上收益，先记录。 |
