## 0. 一页结论

| 问题 | 结论 |
|---|---|
| 现状 | `draw_text` 只跟随平移，**完全不缩放**；肉眼看像 bug（Popup 150ms 缩放动画里文字纹丝不动） |
| 根因 | 字形已光栅化成固定尺寸位图；采样时直接用原尺寸，缩放因子没参与 |
| 两条路线 | **A 重光栅化**（质量最好、每级都要重算）/ **B mipmap 预生成**（O(1) 采样、质量略降） |

| 图集代价 | 完整链 ≈ **1.33×** 面积（1 + 1/4 + 1/16 + 1/64） |
| 最需要拍板的 | **LOD 选择策略**（§2.2）：纯按缩放比，还是能感知笔画密度 |
| 待决策项 | **5 个** |

## 1. 问题定义

### 1.1 现状与后果

`RenderCtx::push_transform(origin, scale)` 已经存在，`SoftBackend::map_point` 会把所有几何点
按栈逐层变换（`soft.rs:246`）。但 `draw_text` 在 `soft.rs:524` 明确写着：

> 文本第一版**只跟随平移，不缩放**（缩放需要重新光栅化或重采样）。

于是：

- **Popup / Tabs 的缩放动画**里，面板、边框、阴影都在放大，**文字纹丝不动**；
- 视觉上不是"文字渲染得不好"，而是"**这个框架有 bug**"；
- 由于动画是 150ms、每帧 `s` 都在变，**重光栅化每帧都发生** → 这是性能风险点，见 §2.1。

### 1.2 形式化

给定：

- 字形位图 `B ∈ [0,1]^{W×H}`（覆盖率图，来自当前光栅化）
- 目标缩放 `s ∈ [0.5, 2.0]`（UI 动画的合理范围）
- 采样核 `K`（后端目前是双线性）

求位图 `B'(s)`，使得 `B' ≈ R_s(B)`，其中 `R_s` 是"在 `s` 倍下重新光栅化"的理想结果，
并按某一度量（§4.3）最小化差异。

**注意这不是纯图像缩放问题**：`R_s(B)` 与 `R_s'(B)`（把位图缩放）在**小尺寸下差异显著**——
缩小时笔画会断、会糊；放大时边缘会方。这正是 mipmap 的收益边界所在。

## 2. 常规做法 vs 创新做法

### 2.1 两条路线的失败场景

| | 常规做法：**重光栅化** | 本设计：**mipmap + 兜底重光栅化** |
|---|---|---|
| 缩放方式 | 每个 `s` 重新走一遍 TTF：轮廓加载 → 扁平化 → 填充 → 抗锯齿 | 预生成 3~4 级位图，O(1) 采样；极端 `s` 才重光栅化 |
| 每帧成本 | **~20–50µs / 字形**（含轮廓+填充），20 个字形 × 60fps 就吃掉 24–60ms/帧 | 采样 **~0.1µs / 像素**，与 `s` 无关 |
| 图集代价 | 每个缩放级别独立占位（N 级 = N 倍） | **≈1.33×**（1 + 1/4 + 1/16 + 1/64） |
| 质量 | 最好 | 略低（缩小时笔画更均匀，但细节损失） |

**常规做法在什么场景下失败**：

1. **动画帧**：Popup 150ms 里 `s` 每帧都不同 → 每帧全量重光栅化，帧率掉到几十毫秒；
2. **图集抖动**：每个新 `s` 都是新位图，Skyline 打包器迅速被填满，
   触发整图重建（`compact_count` 上升）→ 可见的卡顿；
3. **缩放系数连续**：`s` 是浮点，重光栅化无法"缓存"（每个 `s` 都是新缓存项），
   mipmap 则把连续 `s` 量化到有限级。

**mipmap 在什么场景下失败**：

- `s > 2`（放大两倍以上）：低分辨率原图放大 = 边缘发虚，必须重光栅化；
- 极端小字（`s < 0.4`）：笔画会断开，mipmap 只会让它更淡（需要"最小可读尺寸"兜底）。

### 2.2 LOD 选择策略（**本设计的核心**）

朴素做法：`level = round(log2(1/s))`，即纯按缩放比取最近级。

**问题**：同样 `s = 0.7`，"一"（一条横线）和"量"（十几笔）的视觉退化完全不同——
前者缩小后仍然清晰，后者笔画会粘连。纯几何 LOD 对复杂字形过于保守/激进。

`【待决策-①】` 三种候选：

| 方案 | 依据 | 优点 | 缺点 |
|---|---|---|---|
| **A 纯几何** | `level = round(log2(1/s))` | 实现最简单、可预测 | 忽略字形复杂度 |
| **B 覆盖率感知** | 用字形"墨迹覆盖率"（`ink_pixels / (W·H)`）修正 LOD | 复杂字形多降一级、简单字形少降 | 需要在光栅化时额外统计 |
| **C 笔画宽度感知** | 用"最小笔画宽度（像素）"决定是否还能压 | 最贴近可读性 | 笔画宽度估计不稳定（细笔画、衬线） |

**我的倾向：A 为主 + B 作为可选修正**（`B` 只在 `ink > 0.25` 时多降一级）。
理由：A 可预测、B 的统计量在光栅化时顺手就有（填充率已知），C 的估计成本与稳定性都不划算。

### 2.3 存储成本

mipmap 链按 `1/2` 逐级，总面积 `1 + 1/4 + 1/16 + ... = 4/3 ≈ 1.33×`。

现状图集：`2048²`，约 9000 槽（`PADDING=1`、`PIN_LAST=512`）。
按 15px 字形（约 11×12）估算：单字形 132 像素，链后约 176 像素 → **图集可容纳字形数下降约 25%**。
若触发更频繁的整图重建，收益会被抵消——`【待决策-②】`：是否**只对 `s < 1` 生成 mip**（缩小时才需要），
放大走重光栅化？这样面积代价只有 **1.33× → 1.08×**。

## 3. 和现有架构的耦合

### 3.1 图集布局：连续槽位 vs 分级分区

| 方案 | 布局 | 优点 | 缺点 |
|---|---|---|---|
| **A 连续槽位** | 一个字形的 L0..L3 打包在**相邻**区域 | 打包器不用改（Skyline 天然支持任意矩形）；`GlyphInfo` 只存一个基址 | 每级尺寸不同，"相邻"只是同批插入 |
| **B 分级分区** | 图集切成 4 个象限，每级一格 | 各级独立 LRU，驱逐粒度均匀 | 小级浪费（L3 只占 1/8 面积却要 1/4 分区） |

**推荐 A**：现有的 `SkylinePacker` 和 `DirtyRect` 机制**完全不用改**，
只需在插入时把多级依次打进图集，`GlyphInfo` 记每级的 `(atlas_x, atlas_y, w, h)`。
`【待决策-③】` 是否需要"同一字形的多级必须同生共死"（驱逐时一起走）？
若不一起驱逐，采样到缺失的级就会掉回 L0（质量退化但不错误）。

### 3.2 `GlyphInfo` 要不要加 `mip_levels`

现状字段：`width/height/bearing_x/bearing_y/advance/atlas_x/atlas_y/last_used`。

**方案**：加 `mips: [Option<MipLevel>; 3]`，`MipLevel { atlas_x, atlas_y, w, h }`。

- 用定长数组而不是 `Vec`：级数是编译期固定的（3 级），`Vec` 会多一次分配且破坏 `Copy`；
- **L0 就是现有字段**，`mips[0]` 可省，保留 `atlas_x/y/w/h` 语义不变 → **向后兼容**。

`【待决策-④】` 级数：**3 级（1/2, 1/4, 1/8）** 还是 **4 级**？
按 `s ∈ [0.5, 2.0]` 的实际需求，3 级已覆盖到 `s = 0.25`；4 级的边际收益很小。

### 3.3 `scale` 怎么传到字形采样

现状：`draw_text` 里 `map_point(origin)` 只变换起点，每个字形的 `bx/by` 与原尺寸采样。

三条候选：

| 方案 | 做法 | 问题 |
|---|---|---|
| **A `draw_text` 内查** | `RenderCtx` 暴露 `current_scale() -> f32`（从变换栈取乘积），`draw_text` 内部按 `s` 选级 | 后端要新增一个查询方法（默认返回 1.0） |
| B 上层算好传入 | `TextStyle` 加 `scale` 字段 | 破坏 `TextStyle` 语义（它是"样式"不是"几何"），且与变换栈脱钩 |
| **C 完全在 `RenderCtx` 内** | `map_len()` 已能算长度缩放；`draw_text` 用 `map_len(1.0)` 得到 `s` | **无需新 API**，复用现有变换栈 |

**推荐 C**：`SoftBackend` 已有 `map_point`，加一个私有 `map_scale()` 取栈乘积即可，
对外零 API 变更。`【待决策-⑤】` D3D 后端同样需要（`draw_text` 在 GPU 上是逐实例 UV），
是否接受"两后端各自实现 LOD 选择"（会产生轻微视觉差异）？

### 3.4 mipmap 怎么生成

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A 光栅化时直接生成多尺寸** | 对每个级用对应的 `px_size` 重新走 TTF | 质量最好（每级都是真光栅化） | 光栅化成本 ×3，但**一次性**（进缓存后不再付） |
| **B 从 L0 下采样** | 2×2 box filter 逐级降 | 便宜（O(W·H)） | 小尺寸笔画会糊/断（box filter 不考虑字形语义） |

**推荐 A**：mipmap 的意义就是"预先把多级做对"，而 TTF 光栅化在 7px（L1）尺度下仍然比
box filter 准确得多；成本是**进缓存时一次**，不是每帧。

**关键**：TTF 引擎已有 **4 个亚像素相位**（`phase ∈ 0..=3`）。mipmap 链与相位是**正交**的两维：
`(phase, level)` 组合会带来 4×3 = 12 个位图/字形 —— `【待决策-④】` 的一部分：
**缩小时还需要相位吗？** 建议**只对 L0 保留 4 相位**，mip 级别只用 phase 0（缩小后相位差异不可见）。

## 4. 验收标准

### 4.1 必测矩阵

| 维度 | 取值 | 理由 |
|---|---|---|
| `s` | 0.5 / 0.75 / 1.0 / 1.5 / 2.0 | 覆盖缩小的三级、恒等、放大的两条边界 |
| 字符 | `A`（简单拉丁）/ `量`（复杂 CJK） | 简繁字形复杂度差异 |
| 数量 | 单字 / 一行 20 字 | 多字时基线对齐与间距是否仍正确 |
| 后端 | SoftBackend 优先；D3D 至少一个冒烟 | 像素断言在 CPU 上可回读 |

### 4.2 像素断言 vs 几何断言

**两者都要，但用途不同**：

- **几何**：`s = 2.0` 时字形**前进量**必须也是 2 倍（否则字会重叠）。断言 `advance * s`。
- **像素**：`s = 0.5` 时墨迹像素数应约为 `s² ≈ 25%`（允许 ±30% 抗锯齿误差）；
  `s = 1.0` 必须与**当前实现逐像素一致**（回归基线）。

**每一条像素断言都要带"变异对照"**（前几轮的教训）：例如断言"缩放后墨迹数 < 未缩放"，而不只是"有墨"。

### 4.3 质量度量

`【待决策-⑥】`（并入 ①）三选一：

1. **像素差**（MAD）：`mean(|B_mip - B_re) / 255)`；简单、可解释，但对齐敏感；
2. **SSIM**：更贴近人眼，但要实现（约 60 行）或引依赖（框架要求零第三方依赖 → 自写）；
3. **墨迹分布差**：按行/列投影比较——对"笔画断裂"更敏感，正好是 mipmap 的主要缺陷。

**推荐 1 + 3**：MAD 给总体差异，投影差专门抓"笔画断"。SSIM 自写成本高、收益不明确。

### 4.4 性能

| 指标 | 目标 | 依据 |
|---|---|---|
| mip 生成（一次性，每字形） | **≤ 3× 单级光栅化** | 3 级各走一次 TTF；L0 已有 |
| 采样（每帧每字形） | **≤ 1.2× 单级采样** | 只多一次 `log2` + 数组索引 |
| 10k 字形一帧 | ≤ 现有 +10% | 现状 `draw_text` 是逐像素循环，采样成本本就占主导 |

**红线**：如果 mip 生成让**首次输入**（rime 图集冷启动）出现可见停顿（>50ms），
改为**惰性逐级生成**（用到哪级才生成哪级）——这会把成本摊到实际上不需要的级上。

### 4.5 质量验证（实测，已执行）

三项测量，全部 release 构建、62 个 Latin 字形、15px → 7.5px（L1）。

**① 两条路径彼此差多少**（`MAD(重光栅化, 盒式滤波)`）

| 类别 | 样本 | MAD 均值 | 最大 | 最小 |
|---|---|---|---|---|
| 大写 | 26 | 0.1406 | 0.2848 | 0.0016 |
| 小写 | 26 | 0.1342 | 0.3029 | 0.0015 |
| 数字 | 10 | 0.1375 | 0.2667 | 0.0026 |

差异显著（> 0.1）；但**最小 ≈ 0.0015** 说明简单字形（`l`/`I`/`1`）上两者几乎相同。

**② 有偏代理真值**（4× 字号渲染后盒式降到 L1）—— **这条结论不可用**，因为它天生偏袒盒式滤波：

```
重光栅化 MAD 0.3305    盒式滤波 MAD 0.3207    重光栅化更近：33/62
```

**③ 无偏真值（4×4 超采样，独立实现的绕数路径）** —— 这才是判据：

| 类别 | 样本 | 重光栅化 MAD | 盒式滤波 MAD | 谁更近 |
|---|---|---|---|---|
| 大写 | 25 | **0.0194** | 0.1438 | 重光栅化 |
| 小写 | 22 | **0.0208** | 0.1311 | 重光栅化 |
| 数字 | 10 | **0.0162** | 0.1522 | 重光栅化 |
| **合计** | 57 | **0.0194** | **0.1404** | 重光栅化，**5× 更近** |

**对齐修正**：上表按左上角对齐，可能把"整体平移半像素"算成形状差异。允许 ±2px 整体平移后再比：
`重光栅化 0.0194 / 盒式滤波 0.1027` —— **结论不变，仍是重光栅化 5× 更近**。

**结论：设计假设成立（有数据支撑）。** 之前的"代理真值略胜盒式"被无偏测量推翻，
原因是代理真值由盒式降采样构造，**方法本身带偏**。

**超采样实现的可信度**：8×8 纯矩形（解析覆盖率已知）误差 ≤ 1/16（16 个采样点的量化极限），
留边行列恒为 0 —— 这条不过，上面所有数字都作废。

**成本**：62 字形 L1 重光栅化 **855µs**，L2 **950µs**；超采样测量本身 2–3ms（仅测试用）。

## 5. 可复用的抽象

### 5.1 与 Image 缩放的关系

`Image` 的 `ImageStyle::layout` 已经处理了 `Fill/Contain/Cover` 的**源矩形→目标矩形**映射，
后端用双线性采样（`sample_bilinear_tex`，像素中心对齐 `sx - 0.5`）。

**相同点**：都是"位图 + 缩放 + 采样"。
**不同点**：图片的分辨率固定（源图就那么大），字形有**无限精度的源**（TTF 轮廓）。

因此：

- **LOD 选择策略可复用**：`log2` 级的 mip 链、按 `s` 选级、`s > 2` 时"回退到高清源"——
  这套逻辑对两者是一样的；
- **生成策略不可复用**：图片只能 box filter 降采样，字形应该重光栅化。

### 5.2 抽象应该放哪

| 位置 | 内容 | 理由 |
|---|---|---|
| **`y901-render`** | `MipChain`（`level_for(scale)` + `[MipLevel; N]`）、采样选择 | 它已经依赖 `y901-ui`，且是"位图与采样"的归属地；`y901-ui` 不该知道 mipmap |
| `y901-ui` | 只暴露 `current_scale()`（若最终选方案 A） | 语义层只需要"当前缩放是多少" |

**判定规则**（沿用 Grid 那次定的）：*只依赖标准库 + 数值的 → `core`；依赖位图/采样的 → `render`；依赖布局语义的 → `ui`*。
`MipChain` 依赖位图尺寸与采样 → **`y901-render`**。
