## 1. 问题定义

### 1.1 符号

- 脏区集合 `D = {r_1, …, r_n}`，每块为轴对齐矩形，面积 `a(r)`。
- 调度输出：`R = {s_1, …, s_k}`，每块是 scissor 区域（可重叠、可大于脏块）。
- 可行性：`∪ s_j ⊇ ∪ r_i`（覆盖所有脏像素）。
- 代价：

```
cost(R) = k · c_switch + c_pixel · area(∪ s_j)
```

其中 `c_switch` = 一次 scissor/状态切换的固定开销（CPU 侧提交 + GPU 状态），
`c_pixel` = 单位面积清屏+重绘的开销。

**注意 `area(∪ s_j)` 而非 `Σ area(s_j)`**：重叠的 scissor 不会重复付像素代价（同一像素画两次才是浪费，见 §1.3 的说明）。

### 1.2 两段式最优性

对**任意给定分组**（把脏块划成 k 组，第 j 组的 scissor 取其包围盒），min 面积是确定的：
组的包围盒面积。于是问题等价于：

> 把 n 个矩形**划分**成 k 组，使 `k·c_switch + c_pixel·Σ_j area(bbox(group_j))` 最小。

这是**带基数约束的聚类**：k-median 的"目标换成矩形包围盒面积"的变体。

**与已知问题的关系**：

| 问题 | 关系 |
|---|---|
| **k-median / k-medoids** | 同为"选 k 个中心 + 归属"结构；但距离不是度量距离，而是"包围盒面积增量"，不满足三角不等式 |
| **facility location** | 若不固定 k，而是给每次切换定价 `c_switch`，则等价于"开设施付固定费 + 服务付面积"，即**无容量设施选址** |
| **set cover / max-coverage** | 若把"每组包围盒"视为一个集合、脏像素视为元素，则覆盖约束是 set cover；k 固定时是 max-coverage |

### 1.3 为什么"面积"而不是"次数"

同一像素被两个 scissor 各画一次，代价是 `2·c_pixel`；
所以严格代价应为 `c_pixel · Σ_j area(s_j)`（按次数计，重叠重复计费）。

本文采用 `area(∪)` 作为**近似**，理由是：调度器可选择互不重叠的 scissor（把重叠区裁给其中一个），
代价不劣于并集。**该等价性待推导**（需要证明"存在一个不重叠的最优解"，
直觉上成立：把重叠部分只分配给一个 scissor 不会增加任何 scissor 的面积）。

### 1.4 复杂度

**命题（待推导）**：`n` 块脏矩形、预算 `k` 的上述划分问题是 NP-hard。

论证思路（**未完成，标注待推导**）：

1. 取 `c_switch → ∞` 时最优解是 `k = 1`（包围盒），问题退化，故需 `c_switch/c_pixel` 处于中间区间；
2. 该区间内，问题包含 **rectilinear k-median** 作为特例（把每块脏矩形视作点集，包围盒面积 =
   矩形距离的单调函数），而**欧氏/rectilinear k-median 已知 NP-hard**（Kariv–Hakimi 1979；
   Megiddo–Supowit 1984）——但"面积"与"距离和"不等价，**归约需要额外的 gadget**。
3. 另一条更直接的路线：从 **set cover** 归约——构造脏块使"每组包围盒"只能覆盖特定子集，
   即可编码集合覆盖；`k` 固定则得到 max-coverage 的判定版本（已知 NP-hard）。

**结论**：**不宣称已证明**。可作为论文的 open lemma，或用"限制候选族 + 近似比"绕开（见 §3）。

## 2. Baseline 代价（可直接代入）

| 策略 | k | 覆盖面积 | 代价 |
|---|---:|---|---|
| **包围盒**（bbox of all） | 1 | `area(bbox(D))` | `c_switch + c_pixel·area(bbox(D))` |
| **逐块**（no merge） | n | `Σ a(r_i)` | `n·c_switch + c_pixel·Σ a(r_i)` |
| **当前策略**（touches + 上限 16） | ≤16 | 取决于合并顺序，**无界** | 同式，但面积可能远大于两者之间 |
| **整窗**（overflow） | 1 | `W·H` | `c_switch + c_pixel·W·H` |

### 2.1 当前策略的病态例子（这是真实的，不是假设）

两块 1000×1 的细条，`A = [0,0,1000,1]`、`B = [0,1,1,1000]`（在边 `y=1, x∈[0,1]` 相贴）：

- 脏面积 = `1000 + 1000 = 2000` px
- `touches` 为真 → 合并为 `bbox = [0,0,1000,1001]` ≈ **1,001,000 px**
- **放大 500×**

> **这就是"贴边即合并"的代价**：它把"相邻"当成了"应该在一起"，
> 而在细长/角落相邻的布局里（滚动条 + 分隔线、表格网格线、AI 流式输出的逐行增长），这种情形并不罕见。

### 2.2 合并判据（可精确推导的部分）

对两块矩形 `A, B`：

```
area(A ∪ B) = area(A) + area(B) − area(A ∩ B)
```

因此**把 A、B 合成一组**（k 从 2 降到 1）的代价变化为：

```
Δcost = −c_switch + c_pixel · area(A ∩ B)
```

> **合并当且仅当 `c_pixel · area(A ∩ B) ≥ c_switch`。**

这条判据是**精确的**（两块的子问题最优解），且**只依赖重叠面积**，与"是否贴边"无关。
当前 `touches()` 在 `A ∩ B = ∅` 时仍然合并 —— 此时 `Δcost = −c_switch + 0 < 0`，
看似"总能省一次切换"，但**忽略了合并后包围盒可能暴涨**：上式只对"两块"成立，
多块场景里 `area(A∪B)` 用的是包围盒而非真实并集，**这是当前实现的记账错误**。

> 换句话说：`touches` 的合并判据在**两块的精确几何**下是正确的，
> 一旦用 bbox 代替真实并集，`area(A∪B) − area(A) − area(B)` 不再是 `−area(A∩B)`，而可能是任意大。

## 3. 建议算法

### 3.1 A：自底向上的贪心合并（推荐先做，改动最小）

```
while |R| > 1:
    对每一对 (i, j) 计算 Δ_ij = area(bbox(s_i ∪ s_j)) − area(s_i) − area(s_j)   # 即额外覆盖
    选 Δ 最小的一对合并，仅当 c_pixel·Δ < c_switch
```

- 复杂度：`O(n² log n)`（n ≤ 16 时实测量级可忽略：最多 120 对）
- 性质：**单调**（每次合并代价不增，因为只在 `c_pixel·Δ < c_switch` 时合并）
- 近似比：**无常数保证**（层次聚类在 k-median 上的下界很差，可构造 `Ω(log n)` 的例子）
- 优点：**可直接替换 `touches()`**，不需要新的数据结构

### 3.2 B：max-coverage 贪心（有可引用的近似比）

把问题**放宽**为"用 k 个矩形最大化覆盖的脏面积"（允许剩余脏区再用一轮处理）：

- 候选族 `C`：所有脏块对（及单个脏块）的包围盒，`|C| = O(n²)`
- 每轮选"新增覆盖脏面积 / 面积代价"最大的候选
- 经典结果：**max-coverage 的贪心是 `(1 − 1/e)` 近似**（Nemhauser–Wolsey–Fisher 1978，
  对单调次模函数成立；"覆盖面积"关于候选集合是次模的）

**注意**：`(1−1/e)` 是**对"覆盖量"**，不是对 §1 的加权代价。
把它映射回成本的界需要额外论证（**待推导**）。论文里可以写成"两阶段：
先保证覆盖，再在覆盖解上做 §3.1 的合并"。

### 3.3 C：k-medoids / Lloyd 风格

固定 `k`，交替：（1）归属：每块脏块并入"增量面积最小"的组；
（2）更新：每组取 bbox。迭代至稳定。

- 单调下降、必收敛（有限状态），但**只保证局部最优**
- 对 `k` 的选择：用 §2 的 `Δcost` 做**二分/递增**——从 `k=n` 开始按 §3.1 合并，
  记录每个 k 的 `cost`，取最小者（n ≤ 16 时可直接枚举所有 k 的合并序列）

### 3.4 D：带状区域（banded region）——**这是工业界的标准解法，必须对比**

`QRegion`（Qt）、`SkRegion`（Skia）、`X11` damage 都用**扫描带**表示：
按 y 扫描线切成若干带，每带内是若干 x 区间。性质：

- **精确**表示（无过度覆盖），带数 ≤ 2n
- 天然给出 scissor 序列：每带一个 scissor，带内多次填充
- 与我们问题的关系：带状是"k = 带数"的一个**特定划分**，不优化 `c_switch` vs 面积

> **prior art 提示（待核实）**：就我所知，**"以 c_switch 与 c_pixel 的显式代价做 k-矩形最优调度"没有作为命名算法出现在桌面 UI 文献里**，
> 但它的**组件**（damage region、banded region、max-coverage 贪心、k-median 聚类）都是标准的。
> 因此本文的贡献点应定位为：
> **(a) 把该权衡显式形式化；(b) 给出"重叠面积 ≥ c_switch/c_pixel"这一精确两块判据；
> (c) 用真实负载证明启发式（贴边合并）在最坏情形下差 500×。**
> 而不是"发明了脏区合并算法"。**文献核实需在有网络的环境补做**（本会话 web 检索不可用）。

## 4. 实验设计

### 4.1 负载

| 负载 | 形状特征 | 生成方式 |
|---|---|---|
| **AI 流式输出** | 小矩形逐帧增长、彼此相邻、常贴边 | 每帧在文本末尾追加 1 行（高度 = 行高），宽度随机 20%~100% |
| **终端滚屏** | 整窗带状、大量重叠 | 每帧整屏上移一行 + 底部一行新内容（脏区 = 全宽 × 2 行） |
| **多控件同时更新** | 散点、互不相邻 | k 个随机位置的固定尺寸控件（如 8 个 120×40） |
| **病态：角落相贴** | §2.1 的构造 | 两条 1000×1 / 1×1000 细条 |
| **混合** | 以上按比例混合 | 每帧随机选一种 |

### 4.2 度量

- `cost`（按 §1 公式，`c_switch`/`c_pixel` 来自 4.3 标定）
- `k`（scissor 切换次数）
- 覆盖面积与**过度覆盖比** `area(∪s)/area(∪D)`
- 帧耗时 p50 / p95（D3D 与 Soft 两个后端分别测）

### 4.3 常数标定（必须先做）

`c_switch`：构造 1×1 脏块，重复 N 次 `SetScissorRect` + 空 draw，测斜率。
`c_pixel`：全窗 `ClearView` 与 1280×800 填充，测 `ns/px`。

**没有这两个数字，本文的所有"最优"都只是符号游戏。**（这也是最容易跳过、最该先做的一步。）

### 4.4 对比矩阵

| 策略 | 需要实现的量 |
|---|---|
| bbox（k=1） | 已有 |
| 逐块（k=n） | 已有（视为不合并） |
| 当前（touches+16） | 已有 |
| **A 贪心合并** | Δ 计算 + 优先队列 |
| **B max-coverage** | 候选生成 + 贪心 |
| **D 带状** | 扫描线切带 |
| 整窗 | 已有（overflow） |

### 4.5 预期结论（可被证伪的假设）

- **H1**：在"AI 流式"与"终端滚屏"上，`touches` 合并与 A 的 `k` 接近，差异 < 10%；
- **H2**：在"角落相贴"与"散点"上，A 显著优于 `touches`（过度覆盖比 ≥ 5×）；
- **H3**：当 `c_switch` 很小时（`c_switch < c_pixel·overlap_min`），**逐块**反而最优 ——
  即"合并总是好的"是错的，存在**交叉点** `k*`。
- **H4**（最关键）：`k*` 与 `c_switch / (c_pixel · mean_overlap)` 强相关 ——
  若成立，可用一个**闭式阈值**替代所有聚类算法。

> H4 若成立，论文的算法部分可以极简：**阈值规则**，而不是启发式聚类。
> 这是我认为最值得验证的一条。

## 5. 与框架的集成

### 5.1 数据结构：不需要改 `DirtyRegion`，但需要"延迟决策"

`DirtyRegion` 的职责应保持为**收集**（add / full / rects），
**调度**（选 k 个 scissor）应移到 `plan_dirty_rects`。

**关键改动**：`DirtyRegion::add` 里的 `touches` 合并**必须移除或降级为"只做包含关系消除"**，
否则收集阶段的信息已被不可逆地压扁，调度阶段无法再优化。

> 这是一个**语义变更**：`rects()` 的数量会变多（上限 16 仍在），
> 而"贴边合并"带来的脏块减少将由 `plan_dirty_rects` 接管。
> 现有测试 `dirty_and_popup.rs` / `dirty_union_shrink.rs` 需要复核——它们断言的是**当前启发式的结果**，
> 而不是"正确的行为"，很可能需要更新期望值。**这是本设计最大的迁移风险，必须显式列出。**

### 5.2 API

```rust
// 现状
fn plan_dirty_rects(dirty: &DirtyRegion) -> Option<Vec<(i32,i32,i32,i32)>>;

// 建议：参数化 + 可测
pub struct DirtyPlanParams {
    pub max_rects: usize,      // 原 MAX_DIRTY_RECTS = 16
    pub c_switch: f32,         // 标定值（§4.3）
    pub c_pixel: f32,
    pub strategy: DirtyStrategy, // Bbox | PerRect | Merge | Banded | Current
}

pub fn plan_dirty_rects(dirty: &DirtyRegion, p: &DirtyPlanParams)
    -> Option<Vec<(i32,i32,i32,i32)>>;
```

- `strategy` 参数使 §4.4 的对比矩阵**可在同一二进制里跑**，不需要多套构建
- `c_switch/c_pixel` 允许为 0 → 退化为"逐块"；允许为 ∞ → 退化为 bbox（便于测试边界）

### 5.3 对现有测试的影响（预判）

| 测试 | 影响 |
|---|---|
| `dirty_and_popup.rs`（`plan_dirty_rects` 返回 `None`） | 若移除 touches 合并，达到 16 块的路径变化 → 需复核 |
| `dirty_union_shrink.rs` | 断言"合并后面积缩小"，与"不合并"直接冲突 → **必须更新** |
| `black_screen_regression.rs` 的脏区守卫 | 不受影响（只看 `tree.dirty().is_empty()`） |
| 像素哈希基线 | **不受影响**（scissor 划分不改变最终像素，只改变绘制路径）——这是本改动的**安全网**：哈希不变即证明"只是更快，没有画错" |

> **像素哈希是本设计的正确性判据**：只要 `0xDBB308DD1657EF9C` 不变，
> 任何调度策略都不可能改变输出。这使"性能优化"与"视觉回归"可以解耦验证。

## 6. 建议的实施顺序（每步都可独立验证）

1. **先标定** `c_switch` / `c_pixel`（§4.3）——没有这两个数，后面都是空谈；
2. **先加 `Banded` 与 `PerRect` 策略**（不改 `DirtyRegion`），用 `strategy` 参数跑 §4.4 对比 ——
   建立 baseline 矩阵，**不改任何现有行为**；
3. 再实现 **A（贪心合并）**，与 baseline 同矩阵对比；
4. 最后才考虑 **移除 `add()` 里的 `touches` 合并**（迁移风险最高，且有测试冲突）；
5. 每一步都用**像素哈希**做无回归证明。

> **不建议**先改 `DirtyRegion`：那是不可逆的信息损失，且会把"算法对比"和"行为迁移"两件事混在一起。

## 8. 后端无关性的修正（实测后新增）

原代价函数 `k·c_switch + c_pixel·area(∪s)` **在 D3D 上是错的**。实测（见
`docs/design/dirty-scissor-calibration.md`）：

| 后端 | 每次"脏区绘制"的代价 | 最优策略 |
|---|---|---|
| CPU（Soft） | `c_switch ≈ 1.8 ns` ≈ **10 像素** | **逐块**，合并几乎从不划算 |
| D3D | `c_rect = c_scissor + c_draw(N)`，`c_draw` 随实例数线性增长（10k 实例 ≈ 1.6 ms） | **激进合并**，每多一块 ≈ 一次全量 draw |

**结论**：`plan_dirty_rects` **不该是后端无关的策略**。它需要后端提供两个常数：

- `c_rect`：绘制一块脏区的代价（含 scissor + 可能的全量 draw）
- `c_pixel`：每像素填充的代价

由**后端**回答"合并是否划算"，而不是由一个全局启发式决定。

### 下一步（架构级，未实施）

- 在 `RenderBackend`（或等价 trait）加 `fn dirty_merge_threshold(&self) -> Option<(f64, f64)>`
- `plan_dirty_rects` 依据该阈值决定合并策略
- CPU 后端返回 `(≈10, 1.0)`；D3D 后端返回 `(≫10⁴, 1.0)`

### 已实施的部分（本轮）

`DirtyRegion::add` 的合并判据已从 `touches()`（边贴边即可合并）改为 `overlaps()`（**仅真实重叠**）。
理由**不依赖任何后端常数**：
